`node_modules` folders are rebuildable: delete one and `npm install` (or `pnpm install`, or `yarn`) puts it back. That makes them the easiest disk space to reclaim on a developer machine. Here's how to do it for every project at once, in three steps: **list, measure, then delete.**

## Step 1: list them

Always look before you delete. Run these from the folder that holds your projects, not from `/` or your whole home folder on the first try.

<CommandTabs
  client:visible
  id="list"
  tabs={[
    { label: "macOS / Linux", code: "find . -name node_modules -type d -prune -print" },
    { label: "PowerShell", code: "Get-ChildItem -Path . -Directory -Recurse -Filter node_modules -ErrorAction SilentlyContinue |\n  Where-Object { $_.FullName -notmatch 'node_modules.+node_modules' } |\n  Select-Object -ExpandProperty FullName" },
    { label: "cmd.exe", code: "dir /s /b /ad node_modules" },
  ]}
/>

`-prune` matters: it stops `find` from descending into a `node_modules` it has already found, so you get only the top-level folder for each project, and the command finishes far sooner.

## Step 2: measure them

<CommandTabs
  client:visible
  id="size"
  tabs={[
    { label: "macOS / Linux", code: "find . -name node_modules -type d -prune -exec du -sh {} + | sort -h" },
    { label: "PowerShell", code: "Get-ChildItem -Path . -Directory -Recurse -Filter node_modules -ErrorAction SilentlyContinue |\n  Where-Object { $_.FullName -notmatch 'node_modules.+node_modules' } |\n  ForEach-Object {\n    $size = (Get-ChildItem $_.FullName -Recurse -File -Force -ErrorAction SilentlyContinue | Measure-Object Length -Sum).Sum\n    [pscustomobject]@{ MB = [math]::Round($size / 1MB); Path = $_.FullName }\n  } | Sort-Object MB" },
  ]}
/>

The biggest folders are usually old projects using heavy frameworks, or monorepos. That's where to start.

## Step 3: delete them

## What's safe to delete, and what isn't

The blind `find … rm -rf` approach treats every folder named `node_modules` the same. Most are safe, but not every folder with a familiar name is generated, and not every generated folder is worth deleting.

<SafeToDelete client:visible />

A few things to watch for:

- **Global installs.** Tools installed with `npm install -g` live in a `node_modules` folder too (for example under `/usr/local/lib` or your Node version manager's directory). Deleting it breaks those CLIs. Don't run the command from `/` or your Node install folder.
- **Apps that ship a `node_modules`.** Some desktop apps and extensions bundle a `node_modules` folder that they need to run. Keep the search inside your projects folder.
- **Locally patched dependencies.** If you edited a file inside `node_modules` (or use a patching tool that hasn't been committed), it's gone after deletion.
- **Lockfiles stay.** Don't delete `package-lock.json`, `pnpm-lock.yaml` or `yarn.lock`. They're tiny and they're what makes the reinstall reproducible.

## Getting a project back

When you return to a project, reinstall from the lockfile:

```bash
npm ci        # npm, exact versions from package-lock.json
pnpm install  # pnpm
yarn install  # Yarn
```

That's it: the folder you deleted was always a cache of what those commands produce.
