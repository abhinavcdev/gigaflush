Docker never deletes anything on its own. Every image you pulled, every container you stopped, every build layer and every volume stays until you remove it. After a few months that's easily 50 GB. The good news: Docker can tell you exactly where the space went, and most of it is safe to reclaim.

## Step 1: see what Docker is holding

```bash
docker system df          # summary: images, containers, volumes, build cache
docker system df -v       # per image, container and volume
```

The **RECLAIMABLE** column is what you'd get back by removing everything not currently in use. Build cache and unused images are usually the biggest lines.

## Volumes: look before you delete

Volumes are where containers keep data that should survive, like a local Postgres or Redis. That's the one category you can't rebuild.

```bash
docker volume ls
docker volume ls -f dangling=true     # not used by any container
docker volume prune                    # anonymous unused volumes
docker volume prune -a                 # all unused volumes, named ones too
```

<Callout type="warn" title="Check named volumes first">
  A volume named `myapp_pgdata` with no container attached might still be the only copy of a database you care about. Remove volumes by name with `docker volume rm` once you've checked, rather than pruning blindly.
</Callout>

## Docker Desktop: why the disk doesn't shrink

On macOS and Windows, Docker runs in a Linux virtual machine whose disk is a single file. Pruning frees space **inside** that file, but the file itself may not shrink right away.

- **macOS:** the disk image lives at `~/Library/Containers/com.docker.docker/Data/vms/0/data/Docker.raw`. It's a sparse file, so Finder can report its maximum size rather than what it uses; `du -sh` on it shows the real usage. You can lower its size limit under **Settings → Resources → Advanced** (the disk image or virtual disk limit, depending on your Docker Desktop version).
- **Windows (WSL 2):** the data lives in a `.vhdx` file that grows but doesn't shrink on its own. After pruning, run `wsl --shutdown`, then compact the file with `Optimize-VHD` (Hyper-V tools) or `diskpart`'s `compact vdisk`.
- **Starting over:** Docker Desktop's **Troubleshoot → Clean / Purge data** removes everything at once. It deletes all images, containers and volumes.

## Keep it from filling up again

- Set a BuildKit garbage-collection limit in Docker Desktop's **Docker Engine** settings (`"builder": { "gc": { "enabled": true, "defaultKeepStorage": "20GB" } }`).
- Use `docker run --rm` for one-off containers so they delete themselves on exit.
- Run `docker system df` once a month; it takes a second.
