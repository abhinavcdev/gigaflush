"Your disk is almost full" doesn't say what filled it. Before deleting anything, find out where the space went. These are the fastest ways to get that answer, from one-line commands to visual maps of your whole drive.

## In the terminal: du

`du` (disk usage) is on every Mac and Linux machine. The trick is sorting the output.

<CommandTabs
  client:visible
  id="du"
  tabs={[
    { label: "This folder", code: "du -sh * .[!.]* 2>/dev/null | sort -h", note: "Each item in the current folder, smallest to largest, including hidden ones." },
    { label: "Your home folder", code: "du -h -d 1 ~ 2>/dev/null | sort -h | tail -20", note: "-d 1 means one level deep. On Linux, --max-depth=1 does the same." },
    { label: "Largest files", code: "find ~ -type f -size +1G -exec ls -lh {} + 2>/dev/null | sort -k5 -h", note: "Every file over 1 GB under your home folder." },
  ]}
/>

<Callout type="tip" title="Start one level down">
  Run `du` on your home folder first, then on the largest folder it shows, and keep going. Pointing it at `/` straight away is slow and full of permission errors.
</Callout>

## Interactive tools for the terminal

These show a browsable list and let you drill down with arrow keys, which is much faster than re-running `du`.

On macOS there's also **System Settings → General → Storage**, which is good for the big picture but tends to lump developer files into "Developer" or "System Data". Graphical tools such as GrandPerspective, DaisyDisk or OmniDiskSweeper show exactly which folders those are.

## What you'll usually find on a developer machine

Once you're looking, the same names show up again and again:

- **Project dependencies and build output:** `node_modules`, Rust `target`, Flutter `build` and `.dart_tool`, Swift `.build`, Gradle and Maven output. One copy per project, so they multiply with every repo you've cloned.
- **Global caches:** npm, pnpm, Yarn, Cargo, Gradle and pip. See [clearing the JavaScript package manager caches](/blog/clear-npm-pnpm-yarn-bun-cache).
- **Platform tooling:** [Xcode DerivedData and simulators](/blog/xcode-deriveddata-safe-to-delete), [Android Studio emulators and SDKs](/blog/android-studio-disk-space), and [Docker images and build cache](/blog/docker-disk-space-cleanup).

The first group is the one that keeps growing as you start projects, and it's where Gigaflush comes in: instead of finding each folder by hand, it scans your projects for those folders, checks each sits next to its project file, and shows them by size so you can remove the ones from projects you've finished.
