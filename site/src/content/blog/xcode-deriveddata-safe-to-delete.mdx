If you build for Apple platforms, Xcode is likely the biggest developer item on your Mac. Most of it isn't the app itself but what it accumulates in `~/Library/Developer`: build caches, device symbols, archives and simulator runtimes. Some of it is disposable, and some of it you'll want to keep. Here's which is which.

## Measure first

## DerivedData: safe to delete

`~/Library/Developer/Xcode/DerivedData` holds build products, intermediate object files, module caches and the search index for every project you've opened. It grows with each project and each Xcode version, and nothing cleans it up on its own.

Deleting it is safe. Quit Xcode first, then:

```bash
rm -rf ~/Library/Developer/Xcode/DerivedData/*
```

The next build is a full one and Xcode re-indexes the project, so expect one slow build. For a single project, **Product → Clean Build Folder** (⇧⌘K) clears just its build products.

<Callout type="tip" title="Fixes odd build errors too">
  Clearing DerivedData is the classic fix for stale index errors, "module not found" after a package update, and SwiftUI previews that won't load. It's worth trying before anything more drastic.
</Callout>

## iOS DeviceSupport: safe, with a short wait

`~/Library/Developer/Xcode/iOS DeviceSupport` (and similar folders for watchOS and tvOS) stores symbols copied from each OS version of each device you've plugged in. Every iOS update adds a few gigabytes. Delete the versions you no longer debug on; Xcode copies them again when you next connect a device on that version.

## Simulators: delete what you don't use

Simulator runtimes are often the largest item of all, several gigabytes each.

## Archives: keep the ones you shipped

`~/Library/Developer/Xcode/Archives` holds every build you archived for TestFlight or the App Store. Each contains the dSYM files you need to symbolicate crash reports from that version. Delete archives for test builds and versions no one runs any more; keep the rest. In Xcode, **Window → Organizer → Archives** lets you delete them one at a time.

## Smaller items worth a look

- **`~/Library/Caches/com.apple.dt.Xcode`**: Xcode's own caches. Safe to delete while Xcode is closed.
- **`~/Library/Caches/org.swift.swiftpm`**: downloaded Swift packages, shared across projects. Safe; packages download again on resolve.
- **Old Xcode versions**: if you keep `Xcode-beta.app` or an older release around, each one is 10 GB or more.

## Your projects' own build folders

DerivedData isn't the only build output. Swift packages built from the command line keep a `.build` folder next to `Package.swift`, and if you also build Flutter, React Native or Rust projects, their `build`, `node_modules` and `target` folders sit inside your projects too. Gigaflush finds those project folders across everything you've cloned and removes the ones you pick (see the [Swift .build guide](/clean/swift-build)). It doesn't touch DerivedData or simulators, so use the commands above for those. For the rest of the Mac, the [developer cleanup checklist](/blog/free-up-disk-space-mac-developers) covers Docker, Homebrew and package caches.
